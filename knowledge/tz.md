## 1. Общие сведения

### 1.1 Назначение системы

Система предназначена для внутреннего использования компанией в целях:
- Управления проектами и их жизненным циклом
- Ведения базы поставщиков
- Учёта номенклатуры (позиций) по каждому проекту
- Создания и отслеживания заявок на оплату
- Регистрации фактических платежей
- Разграничения доступа по ролям (администратор / клиент)
- Автоматических уведомлений через Telegram-бот

### 1.2 Целевая аудитория

- **Администраторы** — сотрудники компании с полным доступом к системе
- **Клиенты** — внешние или внутренние пользователи с ограниченным доступом только к своим проектам

### 1.3 Технологический стек

| Компонент | Технология |
|-----------|-----------|
| Backend | FastAPI (Python 3.12) |
| Frontend | React 18 + TypeScript + Vite |
| UI-библиотека | Ant Design (локаль ru_RU) |
| База данных | PostgreSQL 16 |
| ORM | SQLAlchemy (async, asyncpg) |
| Миграции | Alembic |
| Telegram-бот | aiogram |
| Хранилище файлов | S3-совместимое (Hostkey), boto3/aiobotocore |
| Контейнеризация | Docker Compose |
| Аутентификация | JWT (python-jose + passlib/bcrypt) |

### 1.4 Требования к языку

- Весь пользовательский интерфейс — **на русском языке**
- Код, схема БД, API-маршруты, внутренние идентификаторы — **на английском**
- Смешивание языков в UI недопустимо

## 2. Роли и права доступа

### 2.1 Администратор (admin)

- Полный доступ ко всем функциям системы
- Полная видимость всех финансовых данных, включая себестоимость и прибыль
- Может создавать, редактировать и удалять:
  - поставщиков
  - пользователей
  - проекты
  - позиции номенклатуры
  - заявки на оплату
  - платежи (любые, независимо от создателя)
- Видит все проекты всех клиентов

### 2.2 Клиент (client)

- Ограниченный доступ только к назначенным проектам
- **Может:**
  - просматривать свои проекты
  - просматривать заявки на оплату
  - добавлять платежи к заявкам
  - удалять только свои платежи (где `created_by` = собственный ID)
- **Не может:**
  - создавать / редактировать / удалять проекты
  - управлять поставщиками и пользователями
  - управлять номенклатурой
  - создавать / редактировать / удалять заявки на оплату
  - видеть себестоимость (`cost_price`)
  - видеть прибыль (`profit`)

## 3. Аутентификация

### 3.1 Вход в систему

- Стандартная форма: логин + пароль
- Пароли хранятся в виде bcrypt-хешей, никогда в открытом виде
- При неверных учётных данных — сообщение об ошибке на русском языке

### 3.2 JWT-токены

- **Access token** — время жизни 30 минут
- **Refresh token** — время жизни 7 дней
- Обновление access token через `/api/auth/refresh`

### 3.3 Защита от перебора

- Rate limiting на `POST /api/auth/login`: не более 10 запросов в минуту с одного IP

### 3.4 Первоначальные учётные данные

- При первом запуске автоматически создаётся администратор: `admin` / `admin`

## 7. Страница проекта (детальный вид)

- **Правая (60%)** — Заявки на оплату

### 7.1 Левая панель — Номенклатура

#### 7.1.1 Таблица позиций

В таблице отображается: наименование, количество.  
Клик по строке — открывается детальный вид позиции.

#### 7.1.2 Поля позиции

| Поле | Тип | Обязательность | Видимость |
|------|-----|---------------|-----------|
| name | строка | Обязательное | Все |
| details | текст | Необязательное | Все |
| quantity | число (>0) | Обязательное | Все |
| supplier | выбор из поставщиков | Необязательное | Все |
| price | число (≥0) | Обязательное | Все |
| cost_price | число (≥0) | Обязательное | Только admin |
| currency | enum (CNY / USD / RUB) | Обязательное | Все |
| commission | число (%, по умолчанию 0) | Необязательное | Все |

#### 7.1.3 Требования к позиции

- Текстовые записи, добавляемые со временем
- Максимум **5 штук** на позицию (ограничение на уровне API)
- Добавление и удаление по одному

#### 7.1.4 Финансовые расчёты

Формулы (группируются по валюте, вычисляются на лету, не хранятся в БД):

```
effective_price = price * (1 + commission / 100)
total           = SUM(effective_price * quantity)      — по валюте
remaining       = total - paid                          — по валюте
profit          = SUM((effective_price - cost_price) * quantity) — по валюте, только admin
```

Клиент видит: `total` и `remaining` по каждой валюте.  
Администратор видит дополнительно: `profit` по каждой валюте.

**Примечание:** В одном проекте допустимы позиции в разных валютах. Конвертация валют не производится. Все итоги отображаются отдельно для каждой валюты.

#### 7.1.5 CRUD номенклатуры

| Действие | Роль |
|----------|------|
| Добавить позицию | Admin |
| Редактировать позицию | Admin |
| Удалить позицию | Admin |
| Просмотр | Все |

## 8. Платежи

### 8.1 Поля платежа

| Поле | Тип | Обязательность |
|------|-----|---------------|
| amount | число (>0) | Обязательное |
| currency | enum (CNY / USD / RUB) | Обязательное |
| note | текст | Необязательное |
| file | файл (вложение) | Необязательное |

### 8.2 Логика платежей

- Каждый платёж уменьшает остаток заявки
- Заявка считается **закрытой** при `remaining = 0` (отображается статус «Оплачено»)
- При `remaining = 0` форма добавления платежа скрывается

### 8.3 Удаление платежей

| Действие | Кто может |
|----------|-----------|
| Удалить свой платёж | Клиент (только если `created_by` = собственный ID) |
| Удалить любой платёж | Администратор |

## 9. Telegram-бот

### 9.1 Привязка аккаунта

1. Администратор генерирует одноразовую ссылку/токен для пользователя (через UI)
2. Пользователь отправляет боту команду `/start <token>`
3. Бот обращается к backend (`POST /api/bot/verify-link` с `X-Bot-Secret`)
4. При успехе — `telegram_chat_id` записывается в профиль пользователя
5. Ненастроенные пользователи не вызывают ошибок — уведомления просто не отправляются

### 9.2 Уведомления

| Событие | Кому |
|---------|------|
| Создана заявка на оплату | Клиенту проекта |
| Добавлен платёж | Всем администраторам |

Уведомления отправляются асинхронно (fire-and-forget), ошибки логируются.

**Содержимое уведомления:** полная информация о заявке / платеже.

## 10. Схема базы данных

### Таблицы (9 штук)

#### users
```
id, full_name, login, password_hash, role,
description, telegram_chat_id, created_at, updated_at
```

#### suppliers
```
id, full_name, phone, wechat_id,
document_1, document_2, document_3,
description, created_at, updated_at
```

#### projects
```
id, project_number, name, description,
client_id → users(id), status,
created_at, updated_at
```

#### project_items
```
id, project_id → projects(id) CASCADE,
name, details, quantity,
supplier_id → suppliers(id) SET NULL,
price, cost_price, currency, commission,
created_at, updated_at
```

#### project_item_requirements
```
id, item_id → project_items(id) CASCADE,
text, created_at
[макс. 5 на позицию]
```

#### payment_requests
```
id, project_id → projects(id) RESTRICT,
total_amount, currency, requisites, payment_details,
created_by → users(id),
created_at, updated_at
```

#### payment_request_items
```
id, payment_request_id → payment_requests(id) CASCADE,
project_item_id → project_items(id) CASCADE,
amount
[уникальная пара payment_request_id + project_item_id]
```

#### payment_request_attachments
```
id, payment_request_id → payment_requests(id) CASCADE,
file_path, file_name, created_at
[макс. 3 на заявку]
```

#### payments
```
id, payment_request_id → payment_requests(id) RESTRICT,
amount, currency, file_path, file_name, note,
created_by → users(id), created_at
```

### Правила удаления

| Сущность | Правило |
|----------|---------|
| Проект | Блокируется, если есть заявки на оплату |
| Заявка на оплату | Блокируется, если есть платежи |
| Поставщик | Разрешено, SET NULL в project_items.supplier_id |
| Пользователь | Блокируется, если назначен на проект |

## 11. API-эндпоинты

### Аутентификация
```
POST /api/auth/login              — вход (логин + пароль)
POST /api/auth/refresh            — обновление access token
GET  /api/auth/me                 — текущий пользователь
```

### Пользователи (только admin)
```
GET    /api/users                 — список
POST   /api/users                 — создать
GET    /api/users/{id}            — детали
PUT    /api/users/{id}            — обновить
DELETE /api/users/{id}            — удалить
POST   /api/users/{id}/telegram-link — сгенерировать токен привязки Telegram
```

### Поставщики (только admin)
```
GET    /api/suppliers             — список
POST   /api/suppliers             — создать (multipart)
GET    /api/suppliers/{id}        — детали
PUT    /api/suppliers/{id}        — обновить
DELETE /api/suppliers/{id}        — удалить
POST   /api/suppliers/{id}/documents — загрузить документ (slot + file)
DELETE /api/suppliers/{id}/documents/{slot} — удалить документ
```

### Проекты
```
GET    /api/projects              — список (admin=все, client=свои; фильтр по статусу)
POST   /api/projects              — создать (admin)
GET    /api/projects/{id}         — детали
PUT    /api/projects/{id}         — обновить (admin)
DELETE /api/projects/{id}         — удалить (admin)
GET    /api/projects/{id}/summary — финансовая сводка по валютам
```

### Номенклатура
```
GET    /api/projects/{id}/items                              — список
POST   /api/projects/{id}/items                              — создать (admin)
GET    /api/projects/{id}/items/{item_id}                    — детали
PUT    /api/projects/{id}/items/{item_id}                    — обновить (admin)
DELETE /api/projects/{id}/items/{item_id}                    — удалить (admin)
```

### Требования к позициям
```
GET    /api/projects/{id}/items/{item_id}/requirements             — список
POST   /api/projects/{id}/items/{item_id}/requirements             — добавить (admin, макс. 5)
DELETE /api/projects/{id}/items/{item_id}/requirements/{req_id}    — удалить (admin)
```

### Заявки на оплату
```
GET    /api/projects/{id}/payment-requests              — список с remaining_amount
POST   /api/projects/{id}/payment-requests              — создать (admin, multipart)
GET    /api/projects/{id}/payment-requests/{req_id}     — детали (позиции + платежи)
PUT    /api/projects/{id}/payment-requests/{req_id}     — обновить (admin)
DELETE /api/projects/{id}/payment-requests/{req_id}     — удалить (admin)
```

### Платежи
```
GET    /api/payment-requests/{req_id}/payments           — список
POST   /api/payment-requests/{req_id}/payments           — добавить (multipart)
DELETE /api/payment-requests/{req_id}/payments/{pay_id}  — удалить
```

### Файлы
```
GET /api/files/download-url?key=...  — получить presigned URL для скачивания
```

### Бот (внутренний)
```
POST /api/bot/verify-link            — привязка Telegram (X-Bot-Secret)
```

```
/login              → Страница входа

  /database/suppliers → Вкладка поставщиков
  /database/users     → Вкладка пользователей

/projects/:id       → Страница проекта (2 панели)
*                   → Страница 404
```

## 13. Безопасность

- Пароли: bcrypt, без plaintext
- JWT: access 30 мин, refresh 7 дней
- Rate limiting: логин — 10 запросов/мин с IP
- Файлы: валидация MIME-типа, лимит 10 МБ, случайные имена в S3
- IDOR: проверка `client_id` при каждом запросе клиента
- `cost_price` и `profit` исключены из всех ответов API для клиента
- CORS настроен
